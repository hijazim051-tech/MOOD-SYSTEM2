MOOD SYSTEM — مراجعة نهائية 2026-08-30
======================================

هذه النسخة مبنية على Mood-system2(16) وتجمع كل إصلاحات المراحل السابقة.

آخر إصلاحات المراجعة النهائية:
1) تفعيل صلاحيات الصفحات المخزنة في app_permissions / role_permissions / user_permission_overrides داخل الواجهة فعليًا، مع بقاء صفحات غير المسجلة في نظام page.* على قواعد الأدوار الحالية.
2) منع المستخدم المعطل أو الحساب الذي لا يملك user_profile من البقاء داخل النظام بعد Refresh.
3) عزل إشعارات الطلبات والمخزون والجاهزات حسب الفرع المحدد، وإعادة تحميلها فور تغيير الفرع.
4) صفحة الرصيد الحالي تعرض بيانات الفرع الرئيسي القديمة ذات branch_id الفارغ مع بيانات MAIN بدل اختفائها.
5) تقوية SQL المرتجعات: ضمان وجود branch_id في order_returns وربط السجلات القديمة بفرع الطلب قبل استعمال الدالة الجديدة.
6) فحص نحوي لكل ملفات TypeScript/TSX في src: 112 ملف، بدون أخطاء Syntax.

التحديثات المجمعة من النسخ السابقة تشمل:
- مسودة تلقائية لفاتورة المشتريات.
- إظهار بيانات MOOD القديمة دون خلطها مع Alpha.
- تعديل المخزون وحد التنبيه 0 = بدون تنبيه.
- إدارة الحسابات وكلمات المرور عبر manage-user.
- دورة الطلب: تغليف، جاهز، توصيل، مندوب، تحصيل.
- الإلغاء والمرتجعات وإرجاع المخزون الصحيح للفرع.
- الربح والتقارير مع الخصومات والتوصيل والمصروفات والهالك والمرتجعات.
- دفعات الموردين وتأثيرها على الكاش/المصرف وتحديث الدين.
- الرصيد اليدوي والتسويات مع سجل مالي.

طريقة النشر المقترحة:
A) استبدل مشروعك بهذه النسخة.
B) من Terminal داخل apps/client:
   npm install
   npm run build
C) من جذر Mood-system2:
   git add .
   git commit -m "Final MOOD workflow and finance review"
   git push origin main
D) انتظر Vercel حتى يكتمل Production deployment.
E) في Supabase > SQL Editor افتح FINAL_MANUAL_SQL_20260830.sql وشغله يدويًا.
   لا تستخدم supabase db push حاليًا بسبب أسماء migrations القديمة المتكررة.
F) يجب أن تظهر Success / No rows returned. لو ظهر Error لا تعاود تشغيل أجزاء عشوائية؛ احتفظ بالرسالة وصورة الخطأ.

اختبار قبول سريع بعد النشر:
- دخول بحساب owner ثم employee والتأكد من الصلاحيات.
- التبديل بين MOOD وAlpha والتأكد من عدم اختلاط الطلبات/المخزون/الإشعارات.
- إنشاء طلب تجريبي -> تغليف -> جاهز -> مندوب -> تسليم -> تسوية المندوب.
- فاتورة مشتريات تجريبية، الخروج قبل الحفظ، الرجوع والتأكد من استعادة المسودة.
- حفظ فاتورة للمورد بجزء مدفوع ثم تسجيل دفعة لاحقة والتأكد من الدين والكاش/المصرف.
- تسجيل مصروف والتأكد من الرصيد والتقرير.
- مرتجع تجريبي والتأكد من رد المال وعودة الصنف السليم لمخزون الفرع.
- مراجعة Dashboard وReports بعد العمليات السابقة.

ملاحظة build:
تم فحص Syntax محليًا لكل 112 ملف TS/TSX بدون أخطاء. Full npm build لم يكتمل داخل بيئة المراجعة لأن npm ci تجاوز المهلة أثناء تنزيل dependencies، لذلك npm run build على جهازك يبقى خطوة إلزامية قبل git push.
